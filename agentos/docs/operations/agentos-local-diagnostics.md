# AgentOS local readiness and diagnostics (Windows)

The local server exposes `/api/health` as a liveness probe and `/api/readiness` as the launcher readiness contract. `/api/health/ready` is an alias to the same readiness handler; neither alias can turn a failed database or migration check into a ready result.

Readiness reports SQLite integrity and foreign-key checks, registered migration checksums and pending/mismatched migrations, active runtime/recovery state, maintenance lease state, and Provider status. Provider entries include authentication state, CLI version, declared capabilities, and stable error codes. Provider degradation remains visible separately from database readiness. Credential values, raw probe messages, executable paths, workspace/data-root paths, and private configuration are omitted from the diagnostics export at `/api/diagnostics/export`.

`pnpm --filter @agentos/server run build` writes `apps/server/dist/build-identity.json` after TypeScript compilation. The stamp binds the package version, the Git commit captured at build time, and a SHA-256 over the emitted server/workspace JavaScript, lockfile and package manifests, and the shared runtime redactor at `scripts/agentos-diagnostic-redaction.mjs`. Compiled server and CLI processes verify that hash at startup and freeze the identity in memory; they do not read the current checkout `HEAD` or let launcher startup environment override it. A missing or mismatched stamp reports an unavailable identity instead of borrowing a possibly newer Git commit. For source-mode development, readiness marks the package/Git snapshot as `source-checkout` and unverified; use the compiled server and compiled maintenance CLI for release backup/restore matching. When building outside a Git checkout, set `AGENTOS_BUILD_VERSION` and `AGENTOS_BUILD_COMMIT` before the build; `AGENTOS_BUILD_ID` is an optional label that is still suffixed with the compiled-artifact digest.

The Windows launcher starts `apps/server/dist/index.js` and sets `AGENTOS_PROJECT_ROOT` for its data root. It does not infer a build commit from the launcher working directory. `AGENTOS_DATA_ROOT` is retained as a data-root fallback. `AGENTOS_SERVER_INSTANCE_ID` can identify a supervised local instance and is generated when unset or invalid.

Server diagnostic logs are written below `.agentos/logs/diagnostics` in the data root. Each instance log rotates at 8 MiB and retains four numbered files in addition to the active file. Rotation only renames regular files and refuses symlink/reparse-point entries.
