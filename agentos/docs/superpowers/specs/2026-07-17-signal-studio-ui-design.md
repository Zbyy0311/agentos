# AgentOS Signal Studio UI Design

日期：2026-07-17

## 1. 目标

在不改变 AgentOS 现有业务流程、API、状态管理和 Agent 执行逻辑的前提下，统一优化首页与工作区主界面，使产品拥有更清晰的空间层次、更强的执行状态反馈和更稳定的桌面/移动端体验。

本次视觉方向命名为 **Signal Studio**。它吸收 MotionSites 的整屏氛围、GSAP Showcase 的状态感与动效节奏、Awwwards 的编辑式信息层级，但不复制任何外部模板，也不把产品界面改造成营销页面。

## 2. 现状与问题

- 首页当前以深色背景和单一大容器为主，主操作、工作区列表和导入入口的视觉层级还可以更明确。
- 工作区已经具备 Agent 导航、会话历史、聊天、执行检查器四个核心区域，但各面板的表面处理较接近，主会话焦点不够突出。
- 当前主题 token、状态色和按钮基础已存在，但需要进一步统一 panel、selected、input、timeline、empty state 和 motion 的组件语言。
- 响应式行为已有基础策略：小屏隐藏会话历史，较窄屏隐藏执行检查器；本次保留该策略并修正收缩后的层级、边界和可用性。

## 3. 视觉系统

### 3.1 色彩

- 背景使用深色石墨色，不使用纯黑作为唯一页面层。
- 通过 background、surface、raised surface、soft surface 四层区分页面、侧栏、主内容和交互容器。
- 保留暖橙作为品牌 accent，只用于主操作、当前选中、运行中和关键状态。
- success、warning、danger、info 仅承担语义状态，不作为装饰色大面积铺陈。
- 浅色主题沿用同一 token 结构，保持真实白色 raised surface、清晰边界和足够文字对比度。

### 3.2 字体与密度

- 产品 UI 继续使用系统无衬线字体，不引入展示字体或新的字体依赖。
- 首页主标题提升层级和行间距，但工作区内保持固定、紧凑的字号体系。
- 继续使用 8px 间距基线；面板内边距、按钮高度、列表行高和时间线节点保持可预测。
- 正文和长路径控制行宽，避免工作区的工具文本过度拉伸。

### 3.3 表面与边界

- 首页保留一个主工作区容器，列表项使用轻量边界，不让每个对象都成为厚重圆角卡片。
- 工作区使用三栏结构和细边界表达空间分区；只有当前会话、主操作和关键状态使用更强对比。
- 圆角统一为小、中、大三档，不引入新的随机圆角。
- 选中项使用低亮背景、暖橙状态线和文字亮度变化，避免整块高饱和填充。

### 3.4 动效

- 只使用表达状态的动效：hover、focus-visible、active、loading、running、panel reveal 和 toast feedback。
- 默认 transition 控制在 150–220ms，避免页面加载编排或装饰性循环动画。
- 执行中的 Agent 使用轻量呼吸点和时间线当前节点强调；完成、失败、取消使用稳定的语义色收束状态。
- 遵守 `prefers-reduced-motion: reduce`，在减少动态效果模式下关闭非必要 transform、animation 和 scroll behavior。
- 仅使用 CSS，不新增 GSAP 或其他动画运行时依赖。

## 4. 页面设计

### 4.1 首页

首页的第一视觉顺序为：品牌与环境 → 主标题与说明 → 新建工作区 → 工作区列表 → 导入目录。

- 顶部保持简洁，只包含 AgentOS 品牌、环境说明和主题切换。
- 首屏改为左侧主标题与说明、右侧主操作的分栏构图，保留现有中文文案意图，不增加虚构的产品指标。
- 工作区列表容器使用更清晰的标题区和数量信息；列表项显示工作区名称、路径、Git/记忆状态、Agent 数量和最近打开时间。
- 列表项 hover 只做轻微位移/边界强调，整个列表保持稳定，不出现跳动。
- 新建工作区是主按钮；导入目录是次级按钮，并与路径输入框形成连续操作组。
- 空状态说明“创建或导入”下一步，并使用可读的图形/符号，不依赖模糊的装饰文案。
- loading、error 和 empty 状态沿用同一容器边界，避免状态切换时页面跳动。

### 4.2 工作区

保留当前结构：Agent 导航 → 会话历史 → 当前对话 → 执行检查器。

- Agent 导航栏作为轻量 rail：品牌和返回入口在顶部，Agent 列表是主要导航，GROUPS 和项目知识是次级区域。
- 当前 Agent 使用暖橙状态线、低亮背景和头像状态点；运行中状态点与执行检查器同步。
- 会话历史栏强化“当前 Agent/群聊 + 新建会话 + 会话列表”的层级，选中会话只改变背景、状态线和文字亮度。
- 当前聊天区是视觉中心：顶部显示当前 Agent、角色和会话上下文；消息区增加呼吸空间；composer 继续固定在底部并保持发送、附件、模型和思考强度控制。
- 执行检查器作为右侧“状态轨道”：Agent 身份/权限 → 当前状态 → TIMELINE → 执行详情 → 已用时间。时间线节点、连接线和状态标签需具备统一的几何关系。
- 保留现有宽度拖拽和断点行为，改动仅涉及可见层级、边界、状态样式和移动端收缩后的空间利用。

## 5. 实现范围

允许修改的文件：

- `apps/web/src/app/globals.css`
- `apps/web/src/app/page.tsx`
- `apps/web/src/components/workspace/WorkspaceList.tsx`
- `apps/web/src/components/layout/WorkspaceLayout.tsx`
- `apps/web/src/components/chat/AgentList.tsx`
- `apps/web/src/components/chat/ConversationHistory.tsx`
- `apps/web/src/components/chat/ChatPanel.tsx`
- `apps/web/src/components/chat/ExecutionInspector.tsx`

实现约束：

- 不修改 API、服务端、共享类型、Agent 执行逻辑和现有交互状态模型。
- 不新增依赖，不引入新的 UI 框架或动画库。
- 保留主题持久化、工作区动态面板宽度、会话选择、消息发送、附件、运行取消、执行详情、记忆面板和 toast 行为。
- 不触碰当前工作树中与本次 UI 无关的用户改动。

## 6. 验收标准

### 视觉

1. 首页首屏能快速识别主操作、工作区列表和导入入口。
2. 首页空状态、加载状态、错误状态与主容器保持一致的视觉语言。
3. 工作区三栏层级清楚，当前聊天是视觉中心，执行时间线可快速扫描。
4. 深色和浅色主题都具有清晰的背景/表面/边界/文字层级。
5. hover、focus-visible、selected、disabled、loading、running、success、error 状态使用统一组件语言。
6. 视觉动效不影响阅读，不引入持续装饰性动画。

### 响应式

1. 1280px 左右桌面视图无遮挡、溢出或不可读文本。
2. 390px 左右移动视图无横向滚动，Agent 入口、当前会话和 composer 仍可用。
3. 现有侧栏隐藏和面板拖拽逻辑没有回归。

### 功能与工程

1. 主题切换、打开工作区、删除工作区、导入目录、新建工作区仍可用。
2. 工作区中的 Agent 选择、会话选择、新建会话、输入框、发送/取消和状态时间线仍可用。
3. `pnpm --filter @agentos/web run build` 通过。
4. 浏览器检查首页和工作区时无新的 console error/warn，无框架错误覆盖层。
5. 运行现有前端相关测试；如仓库未提供完整 UI e2e，则使用浏览器做核心路径 smoke check。

## 7. 验证计划

1. 启动现有本地 server mock 与 Next.js web。
2. 在 Browser 中检查首页：页面身份、非空渲染、主题切换、输入框状态和工作区入口。
3. 在 Browser 中检查工作区：Agent/会话选择、composer 可用性、执行检查器和时间线展示。
4. 分别检查桌面尺寸和约 390px 移动尺寸，记录布局、文字、边界和状态差异。
5. 运行构建和相关测试；对可见问题回到 CSS/组件进行小范围修复后重复验证。
