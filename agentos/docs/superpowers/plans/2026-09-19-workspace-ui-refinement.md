## 1. 采纳结论

| 原建议 | 决策 | 具体处理 |

| 2. 不同内容采用不同宽度 | 采纳，P0 | Agent 输出取消百分比窄卡限制；正文控制行长，代码、表格、Diff、Artifact 使用内容区全宽。 |

| 4. Run Status 去重 | 采纳，P1 | 一个总状态摘要，过程信息逐层展开；异常和待用户处理状态保持显著。 |
| 5. 输出升级为执行结果 UI | 有条件采纳，P1 | 展示真实 Run/步骤/工具/Artifact 投影，保留完整 Markdown；模型文字不能产生可信完成、文件修改或测试通过标记。 |

| 10. Agent 动态状态 | 部分已有，P2 完善 | 已有 presence、状态点、activity；完善可读性和折叠态提示，不重复建设状态来源或新增轮询。 |

优先顺序：R0-Core 当前使用阻塞 → R1 阅读空间/Composer → 第一轮浏览器验收 → R2/R3 Header/Inspector → 第二轮视觉验收 → R4 Runtime Result Projection 独立数据验收 → R0-Edge/R5 完整收口。

## 2. 边界与既有决定

- 实施范围：`apps/web` 的 `/workspace/[id]` 与必要前端展示组件、测试、文档。
- 保留现有 Liquid Glass、深浅主题、三栏独立组合、分隔条与每工作区偏好。
- 群聊不显示第二栏；按最新用户要求，@all/@Agent 位于 Composer 底部附件按钮右侧，使用与模式/模型/思考一致的轻量透明按钮，保留选中提示；不恢复输入框上方独立 Mention 条或单独磨砂底板。
- 保留模式/模型/思考选择行为；不恢复 Enter 提示、群聊输入框占位文案、群聊 Header 编辑按钮、图标栏运行时工作台按钮。
- 不改变消息、发送、排队、取消、审批、重连、事件、数据库及服务端契约。
- 不改版 `/runtime`。共享 Markdown、Diff、步骤组件若修改，必须给该路由做回归；差异较大的展示用显式 variant 限定在主工作台。
- UI 不读取本地文件、Git、SQLite 或 Provider 私有日志；所有资源通过已有受控接口与 ID 获取。
- 缺少关联数据时展示缺失状态或原文，不用时间相近、文件名相同、Agent 名称或 Markdown 标题推断真实执行关联。

## 4. 切片与逐项验收

### 4.0 验收等级与判定规则

| 等级 | 含义 | 交付规则 |
|---|---|---|
| MUST | 数据真实性、内容完整性、交互可达性与无障碍底线等不可违反的契约 | 适用项必须通过；失败或未执行即阻止对应切片发布。不得用视觉签字豁免。 |
| SHOULD | 默认应满足的视觉/信息架构质量要求 | 未达成需记录影响、理由、替代方案及跟进项，并由用户/验收负责人明确接受；否则保持待验收。 |
| TARGET | 高度、像素误差、滚动偏移、性能/包体等优化目标 | 记录测量条件与实际值；超目标触发复核，不因微小数值偏差单独使 CI 失败。若同时违反 MUST，仍阻止交付。 |

下方未特别标级的验收要求为 MUST；同一条中标为 SHOULD/TARGET 的子句按各自等级判定。设计值为 TARGET，明确的布局状态、折叠阈值、8px 分隔预算及 ID/状态映射属于既有契约，不因本轮分级而放宽。

例如：MUST 无页面整体横向滚动且完整内容可达；SHOULD 工具栏视觉对齐；TARGET 自动化几何误差 ≤4px。测试必须检查实际滚动、末端文本与操作可达性，不用 `overflow:hidden` 截断内容来满足几何读数。

### UI-R0：补齐布局基线（Core P0 / Edge 收口）

工作：复核上一阶段边界场景；补齐覆盖面板焦点隔离/恢复、分隔条键盘语义、拖拽结束提交偏好；保留布局算法及期望状态/实际停靠状态分离。

拆分与准入：

- **R0-Core（Phase A）**：只修现场可复现、影响当前操作的 blocker。首先冒烟 R0-01/05/06，再检查 R0-07 的打开/关闭/返回操作，以及 R0-04 的正常刷新与存储异常不崩溃。只有出现主区不可达、覆盖面板无法退出、草稿/附件丢失、运行被中断、偏好造成崩溃或恢复后布局不可用时，才进入 Core 修复。无 blocker 则记录结果直接进入 R1，不为 R0 创建无必要重构。
- **R0-Edge（Phase E）**：完成 R0-01–08 全量契约与回归，包括阈值 ±1、pointercancel、写入次数、损坏版本/快照、嵌套焦点、IME/快捷键排除和键盘分隔条。不得以这些尚未暴露为当前 blocker 的边界用例阻塞 R1 开发和第一轮截图。
- 若 Edge 用例已导致当前键盘用户无法退出覆盖面板等实际阻塞，应升级到 Core；分期不等于放弃无障碍。提前浏览器验收属于阶段性证据，不代表全部 R0 已达标或获准完整发布。
- 每个 Core 缺陷记录复现、影响、最小修复及对应 R0 编号；阶段表分别记录 Core/Edge，不能以 Core 通过勾选整条混合验收。

验收：

- R0-01：大屏下导航 full/compact × 会话开/关 × Inspector 开/关八种组合均可达；隐藏第二/第四栏时对应 DOM 停靠列及分隔条占宽为 0，第一栏最小 64px。
- R0-02：拖至 139/140/141px（第一、第二栏）、199/200/201px（Inspector）后松手，只有低于阈值才收起；其余归入合法宽度。恢复使用上次正常宽度；从图标栏拖拽不会把 64px 写为正常栏宽。
- R0-03：拖拽移动期间不写 localStorage；正常释放最多写一次最终偏好。pointercancel 恢复拖拽前组合；页面卸载移除监听和 resizing 标记。
- R0-04：每工作区隔离；刷新还原；损坏 JSON、错误版本、缺失/损坏专注快照、读写存储抛错均不崩溃、不困在专注模式。已存 v2 有效偏好保持兼容。
- R0-05：临时退出停靠不写偏好，放宽窗口后恢复；主动关闭不会自动打开；群聊不改私聊会话栏偏好。
- R0-06：专注退出完整恢复进入前状态和宽度；手动操作退出专注并保留新组合。布局切换不卸载 ChatPanel、不丢草稿/附件、不取消或重开运行。
- R0-07：窄屏覆盖面板一次一个；Tab/Shift+Tab 不进入背景；Escape/关闭/遮罩可关闭并恢复到触发按钮；触发按钮已不存在时恢复到主区可用按钮。嵌套弹窗关闭后先回覆盖面板，Escape 只关闭最上层。
- R0-08：快捷键在 textarea/input/select/contenteditable、IME 组合及模态窗口内不触发布局；按键长按不反复开关。分隔条键盘调整、名称、数值/图标态描述有效且焦点可见。

### UI-R1：消息宽度、代码与 Composer 阅读区（P0）

工作：引入工作台专用 MessageSurface/内容宽度规则，复用普通列表、虚拟列表和流式输出；修复真实换行；保留 Mention 在 Composer 内的工具栏对齐；在现有高度测量基础上完善阅读安全区。

设计值：

- 内容区与 Composer 外框最大 1120px；Agent 消息外框填满内容区；正文段落默认最大 80ch（且不超过 840px/容器宽），代码/表格/Diff/Artifact 使用消息内容全宽。
- 用户气泡维持右对齐、最大 80% 且不超过 760px；系统提示保持轻量，不扩成执行结果卡。
- 文本区域继续可拖高；默认空 Composer 高度 TARGET 128–144px（包含普通单行工具栏；附件、错误和工具栏换行允许增高），窄容器允许 Mention/操作组有序换行，不为高度目标隐藏控件。
- 最后一项可滚到 Header 和底部 chrome 之间的可见区；动态 padding 来自真实高度，不写死 120px。玻璃下的经过内容可见，但不让最后一条消息/按钮永久被盖住。

验收：

- R1-01：宽屏普通、虚拟（101+ 条）及流式 Agent 卡片均不再应用 78%/86% 限制；SHOULD Agent 外框充分使用可用内容区；TARGET 与设计宽度误差 ≤4px，最大宽度设计值 1120px。
- R1-02：300 字符无空格代码行、中文代码注释、200 行 Diff、20 列表格仅在各自容器水平滚动；页面及聊天滚动区无用户可操作的横向滚动条。
- R1-03：换行切换作用到实际 code 元素；开启后长行完整可读，关闭后可滚动到末尾；前后文本内容与顺序一致，不能只隐藏溢出部分。代码/表格滚动不拖动页面。
- R1-04：617–1920px 和专注模式下 Mention 保持在 Composer 内、附件按钮右侧，@all/@Agent 仍按原 ID 选择发送对象，按钮不互相覆盖且可达。SHOULD 与模式/模型/思考保持一致的字号、轻量背景与工具栏对齐，无独立底板；空间足够时同行，不足时有序换行；TARGET 同行控件中心线误差 ≤4px。不再比较 Mention 与 Composer 外框左边界。
- R1-05：空输入、长草稿、1/5 张附件、校验错误、发送排队、运行中停止按钮、Mention 换行与拖高输入框后，最后一个短内容项可完整滚至 chrome 之上；任意位置的正文行都能滚入无遮挡阅读区。TARGET 短内容项底边与 chrome 顶边留白至少 12px；不得靠裁切或隐藏内容达标。
- R1-06：模式/模型/思考显示值不拆字；极长模型名省略并可查看全名。附件按钮与选择器空间足够时同行，不足时按组换行；发送/停止按钮完整可达。
- R1-07：三个选择器的菜单在所有容器宽度下不被玻璃/overflow 裁切，键盘可打开、选择、关闭；为 canvas 限制溢出不能裁掉菜单或焦点环。
- R1-08：跟随底部时流式输出保持可见；主动向上滚动后不强拉到底；增加“回到最新”可见入口。SHOULD 宽度调整/展开结果/消息完成时保留第一条可见消息阅读锚点；TARGET 非主动滚动偏移 ≤8px，代码换行等明确布局操作除外。记录操作类型及偏移，不能通过阻止内容更新来达标。

### UI-R2：轻量 Header 与材质分级（P1）

工作：删除 ACTIVE SESSION 重复眉题，主标题保留会话/Agent 身份；次行显示私聊/群聊等已有信息；状态留给 Inspector 总结。保留圆角玻璃外框和导航/会话/状态/专注按钮；消息和内嵌步骤减少阴影与框中框。

验收：

- R2-01：操作均可达且不重叠；SHOULD 在 622px 高视口中较基线释放阅读高度、标题常态最多两行；TARGET 常规 Header 外框高度 64px。更窄宽度或 200% 缩放允许增高，不以截断必要操作满足高度目标。
- R2-02：标题长文本可截断并查看完整名称；群聊显示成员数必须有真实成员数据，不能用全工作区 Agent 数冒充；没有数据时只显示“群聊”。
- R2-03（SHOULD）：深浅主题保留四角圆角和折射；降低 Header 阴影/折射强度至背景文字不干扰前景阅读的程度，参数通过同一长文本背景截图比较冻结；降低透明度偏好下以实色可读性优先。
- R2-04：普通消息、代码、表格、步骤、统计不新建 WebGL 实例；对正文不施加透明/模糊材质。使用已有语义 token 表达背景、内容、浮层三级，不硬编码仅适配浅色的白色。
- R2-05：此前明确移除的按钮/文字不回归；不删除三栏独立操作入口，也不改变专注模式行为。

### UI-R3：Inspector 总状态与可信指标（P1）

工作：重用并拆分 executionInspector 投影为总状态、当前动作、进度、指标、可展开详情；运行中显示当前工具，完成后收为一行摘要；身份/权限可展开，审批、失败、等待操作持续可见。统一中文状态标签。

范围限制：R3 只重排当前已有明确归属的数据及修正展示映射；不新增历史 Run 请求、缓存、execution/attempt 关联或 SSE 归并引擎。现有数据无法支撑的字段标记缺失，关联能力留给独立 R4，不借 R3 提前混入。

验收：

- R3-01：无运行时显示“尚未开始”。SHOULD 同一总状态区域只出现一个完成标签，不叠加“完成 / Completed / 执行完成”，终态摘要常态一行；步骤自身完成状态允许保留。TARGET 常规终态摘要高度 ≤40px，长文本/缩放可增高，不能裁切异常。
- R3-02：queued、preparing_context、running_cli、streaming_response、waiting_user、completed、failed、cancelled 逐一验证；cancelled 显示“已取消”，不显示 Failed；断线不推断成执行失败。
- R3-03：步骤进度基于稳定步骤 ID 去重，父子层级保留；完成数不含失败/取消/跳过，跳过另计；不从 Markdown 清单推算进度。终态耗时冻结，不用最后一个 Agent 的结束时间冒充整个 Run 的时间。
- R3-04：指标改为键值行，不再用三张小卡和第二处计时；无 Run 时不显示伪零值。真实零值显示 0；未提供显示“未提供”，请求失败显示错误/重试。Token 数据保留 structured/database_delta/unavailable 的来源说明，不重定义 Token 计量方式。
- R3-05：文件数明确标“文件”，不把 created/deleted 文件计数改成代码增删行数；没有文件观测时显示“未记录”，只有来源明确完整的零变更结果才能显示“无文件变更”。
- R3-06：240/280/400px Inspector 均可读；默认折叠工具历史/阶段事件详情，展开后所有已获取项目可访问，不能只保留最后 8 个而无入口。展开区域切换状态时不自动收起、不抢焦点。
- R3-07：失败原因、待用户补充、审批入口不因瘦身隐藏；审批/停止操作仍走原事件处理与接口，模型正文不能生成可信审批控件。

### UI-R4：Runtime Result Projection（独立功能切片，P1，依赖 R1/R3）

产品边界：Conversation → Runtime Projection，而非纯 UI 优化。**最高原则：可信运行事实只能来自明确关联的结构化 Runtime 证据；不得从模型 Markdown 推断成功、测试结果、文件变更、审批或执行归属。无证据即显示缺失/未知或保留原文。** 此原则为 MUST，不能以界面完整、缓存命中或性能优化为由豁免。

隔离交付：独立分支/提交序列、独立 PR、独立数据正确性验收与回滚；PR 基于已验收且可引用的 R1/R3 基线，只包含投影、加载/缓存和相关组件/测试/文档。未合并的依赖显式注明，不能把纯视觉变更捆入 R4。建立“字段来源 → ID 关联 → 缺失/乱序处理 → 测试夹具”审计表后开工；现有契约不足就收缩展示，不补后端契约。R4 不通过时可单独延期，不阻塞已满足自身验收的视觉切片交付。

工作：新增工作台结果摘要与文件列表展示组件；提供“步骤 / 文件 / 产物 / 详情”入口，保留原文。复用 RunTaskTree、ArtifactShelf、DiffBlock、ArtifactPreviewDialog 和已有 Run 详情请求。

数据对应：

| 展示对象 | 已有来源 | 关联和缺失策略 |
|---|---|---|
| 消息与执行摘要 | `ConversationMessage.runId`、`AgentRun`、`AgentExecution` | 通过 workspace/conversation/run ID 关联；无 runId 仅保留普通消息。 |
| Agent 级状态 | Execution 的 agentId/id | 同一 Agent 同一 Run 多次执行不能仅凭姓名匹配；无法唯一关联就显示 Run 级摘要，不给单条消息盖成功章。 |
| 步骤 | `RunStep` 的 runId/executionId/agentId | 稳定 ID、attempt 和事件序号投影；没有步骤不从模型标题生成。 |
| 文件 | `execution.files.changed` / 已有 Run 详情的文件记录 | 按来源 Run 展示路径与变更类型；Agent 归属不明时保留 Run 级。没有旧内容/差异资源不生成虚假 Diff。 |
| Artifact | `RuntimeArtifact` 的 id/runId/sourceExecutionId/agentId | `contentAvailable` 决定能否预览；路径只作显示文本，不能自行组成读取本地文件的链接。 |
| 测试结果 | 当前已有的结构化结果或详情证据 | 本轮不新增测试解析协议；普通工具成功不等于测试通过，Markdown 的 Tests passed 仍为原文。 |

验收：

- R4-01：每个摘要可定位到对应 workspace/run，跨两个 Run、两个 Agent、同 Agent 多次 execution/attempt 的夹具不会串卡或错归属；没有明确关联的字段不展示为事实。
- R4-02：同一 Run 摘要只出现一份，优先放在该 Run 的消息组末尾；历史 Run 详情按需加载，不能把当前 activeRun 数据挂到所有历史消息。普通消息无 runId 时不制造空结果卡。
- R4-03：模型原文完整可展开、选择和复制；Markdown 写“已完成/测试全绿”但服务端 failed 时，结果摘要仍显示失败，原文保留。代码围栏未闭合的流式片段不崩溃。
- R4-04：SSE 重复投递同 eventId 不重复计数，按服务端序号处理；迟到旧事件不回退终态。文件路径重复、修改后删除、重试执行的展示策略与服务端来源一致，不能仅按文件名合并跨 Run 记录。
- R4-05：文件列表显示新增/修改/删除/重命名及来源；重命名旧路径缺失时明确只展示已知路径。无 Diff 资源显示“未提供差异”；Artifact metadata-only、404、403、空文件、超预览大小均有可理解结果且不会打开错误 Run 的内容。
- R4-06：查看详情/产物使用已有 ID 接口；日志复用已有受控详情视图，不把未脱敏 Provider stdout 放入普通卡片。
- R4-07：详情按 workspace/run 缓存及去重，展开同一 Run 不并发重复取数；切换会话后迟到响应不污染新会话。渲染 200 条消息不会发起每条一个详情请求；不新增轮询、Run/发送/取消请求。
- R4-08：加载、空、缺少观测、错误、重试、断线/旧数据状态明确区分；只有原文的历史消息仍完整可读。本轮后端缺失能力记录为限制，不临时扩大 Server/契约范围。

### UI-R5：颜色、间距、语言与导航动态状态（P2）

工作：统一页面展示词汇表及状态 token；常用间距采用已有 4px 基础尺度的 8/12/16/24px；减少说明文字和重复标题。Agent 列表复用已有 presence，保持信息密度。

验收：

- R5-01：栏目/动作/状态使用统一中文，品牌与专业名词保留；无 RUN STATUS+执行状态、ACTIVE SESSION+当前会话的同义双标题。模型输出、用户命名、日志及 API 枚举原值不翻译重写。
- R5-02：强调橙用于品牌/主操作/选中；运行用 info、等待用 warning、成功用 success、失败用 danger、空闲/取消用 neutral；每种状态都有文字和图标，不能只靠颜色。颜色映射集中管理，不复制到多个组件。
- R5-03：full 导航常态保留名称/角色两层；只有运行 activity 有值时显示附加行，长路径省略并可查看完整内容；不为每个 Idle 常驻增加第三行。无 presence 明确显示未获取/未知，不猜成正在执行。
- R5-04：64px 图标栏保留选中标记、名称和状态 tooltip/可访问名称；群聊为空时仍可到达新建群聊入口，偏好/知识入口可达。
- R5-05：无论深浅主题，正文与控件文字对比 ≥4.5:1，必要边界/焦点等非文本标识 ≥3:1，作为本轮无障碍 MUST 而非可豁免性能目标；用实际合成背景检查玻璃前景，而不只比两个 token 色值。主题切换不丢选择和草稿。
- R5-06：prefers-reduced-motion 取消位移、循环 pulse 和背景漂移；prefers-reduced-transparency 使用可读实色表面；无 WebGL2 仍可操作，无空白 canvas 或焦点丢失。

## 5. 完整验收矩阵与证据

### 5.1 固定视口与布局

- 两主题各检查 617、856、1014、1260、1364、1440、1920px；截图统一高度 622px，再对 617/1014/1440px 检查 480px 高度及 200% 缩放。
- 关键临界值各验收 -1/0/+1：712、848、1076、1364px。调整栏宽后另计算一次实际临界值并验证，不能只通过默认常量。
- 默认主区宽度仍为 1260→824px、1440→716px、1014→806px（含每个停靠侧栏 8px 分隔条）；窄屏第一栏保留 64px，页面不被强制撑到 640px 主区。
- 用例覆盖八种独立组合、专注/恢复/手动退出、覆盖面板、群聊/私聊、关闭后刷新、两个工作区隔离、临时收起后窗口增长。
- MUST：页面无整体横向滚动，非资源滚动容器不得靠隐藏内容通过；长资源可在自身容器横向滚动且末端内容可达。TARGET 几何快检 documentElement/body scrollWidth ≤ clientWidth+4px；超差触发实际滚动/截图检查，≤4px 也不能自动豁免真实横向滚动或裁切。记录浏览器版本、DPR、缩放、字体加载状态及容器尺寸，区分 rounding 与真实布局溢出。

### 5.2 数据及内容夹具

- 私聊与群聊：空会话、单条短消息、200 条历史消息、两个不同 Run、同 Agent 多次执行与重试、没有 runId 的旧消息。
- 长内容：连续 10,000 字符正文、300 字符无空格代码行、200 行 Diff、20 列表格、120 字符模型名、240 字符路径、中英文混排、未闭合代码围栏。
- 状态：全部 ExecutionStatus；无运行/无观测/部分观测/真实零/失败/权限拒绝/旧数据/断线恢复；文件四种变更、重复和迟到事件。
- 输入：草稿、中文 IME、附件、排队、校验错误和停止按钮；浮层/侧栏切换前后输入内容、附件 ID 和发送目标保持一致。
- 连续 60 秒模拟 SSE（20 次更新/秒），滚动、拖拽、打开结果详情并切换布局；正文最终值、消息数量和事件序号与夹具一致，不能丢块或重复提交。模拟数据结果必须标注 mock，不代表真实 Provider 验证。

### 5.3 运行与性能验证

- 保持现有 node:test 体系：为状态/来源/去重/缺失处理补必要纯函数测试；组件验证标识、资源入口和原文保留。
- Playwright 使用真实 Chrome，断言 geometry、滚动可达性、焦点循环、快捷键排除、IME 不误发送、内容换行及菜单完整显示；单纯 renderToStaticMarkup 不能替代交互验收。
- 同一机器、同一 Chrome、同一夹具做基线/候选各 3 次 60 秒滚动流式采样；TARGET 交互到下一次绘制 p95 ≤200ms，主线程 >50ms 长任务总时间相对基线增加 ≤10% 或绝对 ≤100ms（二者取更宽容值）。记录每次实测与汇总，未达目标先定位并记录风险，不直接宣称流畅；卡死、输入不可用或丢消息属于 MUST 失败。
- SHOULD 详情重组件按需加载；TARGET 相同构建方式下工作区 First Load JS 增量 ≤10KB gzip，按同一首屏资源集合实测 gzip，不把 Next 构建汇总与 gzip 数字混用；现有基线先实测记录，不以旧摘要数字替代。MUST 保留前一阶段的 WebGL 同屏 context ≤6 资源预算且不因消息数量增加；这是显式资源上限，不按字体/DPR 波动放宽。记录峰值与面板关闭后的释放情况，若要改变预算需单独决策。
- 一次性完成 Web tests、typecheck、生产 build 和 git diff --check；如修改共享组件，补 `/runtime` 渲染/交互冒烟。仅文档计划阶段不运行这些检查。
- 本地 3001 更新到候选生产构建，记录服务工作树与 commit，输出深浅主题前后截图、菜单/覆盖面板截图、浏览器错误日志、验收用例编号与结果。Provider 实跑若执行，记录真实 runId；未执行则明确列为未验证，不能用历史测试代替。

### 5.4 Visual Gate：第二轮与最终视觉完成门

Phase C 完成后进行第二轮视觉验收；Phase E 全量矩阵后再做最终 Visual Gate。Phase B 先验收阅读改善，不等待 R4。审阅对象为同一数据、同一滚动位置的基线/候选深浅主题截图及实际交互；不能只用空会话或静态截图替代运行状态。

| 编号 | 等级 | 视觉完成条件 | 必须提交的证据 |
|---|---|---|---|
| VG-01 信息主次 | SHOULD | Workspace > Message Result > Inspector > Navigation；结果成为主要阅读焦点，导航/装饰不抢占注意力；必须操作的异常提示不受此排序压低 | 1014/1440/1920px 有真实内容的全屏对比，注明主次判断；R4 前用现有消息结果，不造摘要 |
| VG-02 Surface 层级 | SHOULD | Background / Content / Floating 三层可辨；正文实色可读，玻璃限定浮层，降低透明度时仍有层次 | 同一长文本背景下深浅主题截图及 reduced-transparency 对照 |
| VG-03 Card 密度 | SHOULD | 同一视觉层无无意义 Card-in-Card；嵌套只服务真实分组、资源或交互边界，不反复套阴影/边框 | 消息、代码、步骤和 Inspector 局部对比；保留嵌套需注明信息分组理由 |
| VG-04 Accent | SHOULD | 品牌橙仅用于品牌、主操作、Selected；状态使用语义 token，不把 idle 或所有装饰标成强调色 | 标注强调色用途，展示选中/未选中和运行状态对照 |
| VG-05 阅读 | MUST | 正文、代码、Diff 不因装饰缩窄；长内容完整可达，Composer 不遮挡最后内容；缩放和窄屏不以裁切解决溢出 | R1 长内容、换行、safe area 与 200% 缩放交互证据 |
| VG-06 Empty state | SHOULD；真实性为 MUST | Inspector 不用大量 0 / — / 空 Card 填满；以简短状态说明替代重复占位；真实零、缺少观测、加载、失败仍可区分 | 无运行、完整零值、未观测、加载失败四组夹具，不能隐藏缺失或错误来换简洁 |
| VG-07 Runtime | MUST | Running / Waiting / Failed / Approval 有清晰文字、标识和必要操作，不仅靠颜色；审批无独立枚举时依据既有真实审批数据展示，不新增虚假状态 | 运行、等待、失败、待审批与 cancelled 的状态截图/操作；失败原因和审批入口可达，模型文字不能替代证据 |

人工审阅必须逐项填写通过/待改进、截图路径和判断理由，由用户或指定验收负责人确认。SHOULD 未达标按 4.0 记录并批准偏差；MUST 失败不允许豁免。自动化全绿不能自动将 Visual Gate 标记通过；尚无人确认就保持“待视觉验收”。

### 5.5 完成判定

全部 R0–R5 验收条目、共同矩阵与 Visual Gate 均需有等级、结果及证据，或明确标记“不适用”并附数据/范围理由。MUST 适用项全通过；SHOULD 通过或获明确偏差批准；TARGET 有实测、基线对照及超目标分析，不要求所有目标数值机械全绿。失败、未执行、仅模拟验证须分别记录；不得以“已有测试通过”覆盖未测的焦点、长代码和流式行为。

每条记录至少包含：用例编号/子句、等级、所属 Phase/PR、期望、实际结果、环境（浏览器/DPR/字体/缩放）、证据、缺陷或偏差决策。数据真实性、内容完整性、cancelled ≠ failed、无页面横向滚动及输入不中断，不得降级成 TARGET。微小几何差异只报警复核，禁止为压低误差裁切内容、隐藏异常或伪造证据。

纯视觉交付与 R4 分别记录完成状态：R4 延期/阻塞不得宣称全计划完成，但已满足 R0/R1/R2/R3/R5 及其矩阵的视觉部分可独立交付。性能未实测记为未执行，不能借 TARGET 等级省略验证。

交付记录：`docs/acceptance/workspace-ui-refinement.md`，包含基线与最终 SHA、每切片文件范围、自动化结果、截图路径、数据来源/已知限制、真实 Provider 与 mock 的区分、性能对照、Visual Gate 人工决策及回滚方式。R4 单独提供 `docs/acceptance/runtime-result-projection.md`，记录独立 PR/SHA、关联审计表、R4-01–08 数据正确性矩阵和回滚证据；总记录链接该文档，不将视觉截图视为投影正确性的证明。
