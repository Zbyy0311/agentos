## OD-7 — Migration Granularity and Transaction Owner

- Selected Option: **Atomic unit is one source file / Workspace scope。Registry scope is explicit: `scope_kind` is `global` or `workspace`, `scope_key` identifies the source scope, and `canonical_workspace_id` is nullable with `ON DELETE SET NULL`。The sole Evidence UPDATE exception is `canonical_workspace_id: non-null -> NULL` caused by Workspace deletion; every other column must remain byte-for-byte unchanged。After the Execution Lock is held, stale reconciliation, Attempt reservation, and the applicable migration transaction use the defined SQLite boundaries; compatibility rows and Registry state commit in the same SQLite Transaction。**
- Owner Status: **APPROVED — 2026-07-29**

## OD-8 — Migration Idempotency and Completion Marker

- Selected Option: **Dedicated SQLite Registry。After the Execution Lock and before Attempt reservation, an exact completed match on `migration_kind`, `source_key`, `scope_kind`, `scope_key`, `source_hash`, `compatibility_schema_version`, and `hash_algorithm` is a no-op；the old row supplies `payload_hash`, `source_schema_version`, `revision`, and `entity_count` evidence without rerunning Parser。If no exact-source match exists, Parser computes `payload_hash`; source-only hash changes create a new Completed Attempt reusing the Revision；accepted Payload Hash changes create a new Revision；conflict is a Quarantined Attempt with `revision=NULL`；the sole post-terminal UPDATE is non-null canonical Workspace link nulling。**
- Owner Status: **APPROVED — 2026-07-29**
