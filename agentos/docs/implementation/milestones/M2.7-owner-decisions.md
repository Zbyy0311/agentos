## OD-7 — Migration Granularity and Transaction Owner

- Selected Option: **Atomic unit is one source file / Workspace scope。Registry scope is explicit: `scope_kind` is `global` or `workspace`, `scope_key` identifies the source scope, and `canonical_workspace_id` is nullable with `ON DELETE SET NULL`。The sole Evidence UPDATE exception is `canonical_workspace_id: non-null -> NULL` caused by Workspace deletion; every other column must remain byte-for-byte unchanged。Project Runtime Quiescence Ownership is acquired before database-wide Migration Ownership; all Scopes on one canonical database serialize because SQLite Backup and restore are whole-database operations。After both Ownership layers are held, stale reconciliation, Attempt reservation, and the applicable migration transaction use the defined SQLite boundaries; compatibility rows and Registry state commit in the same SQLite Transaction。**

## OD-8 — Migration Idempotency and Completion Marker
