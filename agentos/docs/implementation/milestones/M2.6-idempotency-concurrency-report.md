## 7. Identity

## 8. Fingerprint and Key Normalization

The key is `headerValue.trim()` and the stored key hash is SHA-256 over UTF-8 normalized-key bytes. The request hash canonically includes only `operation`, `workspaceId`, `pathParams`, `domainInput`, and `expectedVersion`; absent expectedVersion is represented as null. Raw key, normalized key, authorization, cookies, headers, raw body, and unknown body fields are excluded.

Raw-header duplicate, case-insensitive duplicate, comma, array, empty, and invalid-character inputs are rejected without echoing the value.

## 9. Typed Envelope

## 12. Idempotency Service

`IdempotencyService` is transactionless. `prepare` hashes outside the transaction; `resolve` reads a verified scoped record; `storeSuccess` inserts only after successful mutation. `PreparedIdempotency` contains no raw or normalized key.

## 13. Six Operation Integration

The six operations are `task.create`, `run.create`, `run.cancel`, `task.accept`, `task.cancel`, and `task.reopen`. TaskRunService owns the single transaction. Resolve is the first domain action; replay precedes all state and version guards; mutation and record insert commit atomically; failed operations leave no record; no placeholder claim, nested transaction, or HTTP retry exists.

## 14. Optional Capability

`createOptionalIdempotencyService` preserves router compatibility with stores that do not expose `idempotencyRepository()`. No-key requests remain compatible. Keyed requests without capability fail closed with `IDEMPOTENCY_RECORD_INVALID` before mutation. Legacy fixtures were not modified.

## 15. Optimistic Concurrency

Optional `expectedVersion` applies only to `run.cancel`, `task.accept`, `task.cancel`, and `task.reopen`. It is parsed only from JSON body and must be a positive safe integer. Absent means undefined at route/service level and null in the fingerprint. The guard runs inside the transaction after replay lookup and before domain/state guards. Matching mutation increments exactly once. Stale values return sanitized 409 `VERSION_CONFLICT`; no current version or entity metadata is exposed. `task.create` and `run.create` retain fingerprint expectedVersion null.

## 16. Error Contract

The fixed public errors are: 400 `VALIDATION_FAILED`; 409 `IDEMPOTENCY_KEY_REUSED` with its frozen safe message; 409 `VERSION_CONFLICT` with `Version conflict`; and 500 `IDEMPOTENCY_RECORD_INVALID` with `Idempotency record is invalid`. Internal SQLite text, stack, key, hash, workspace, and version metadata are not exposed.
