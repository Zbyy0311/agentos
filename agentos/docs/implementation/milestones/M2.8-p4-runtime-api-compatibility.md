## Owner Decision / Plan Contract Assumption Remediation

- Current v2 Task/Run is REST-only: `v2Tasks.ts` exposes create/get/list/run-create/accept/cancel/reopen and `v2Runs.ts` exposes get/cancel; neither exposes `event-stream` or `/stream`.
- No Task-domain Durable Event table or Repository exists. Migration 006 creates the Task-domain `runs` table; migration 009 creates `run_stages`; `default-registry.ts` contains only 001–011. The existing `agent_events`, `execution_events`, and `run_event_sequences` belong to the Conversation runtime and do not create a v2 Task-domain Event Store.
- The current Web has no v2 stream consumer. `apps/web/src/lib/useTask.ts` uses the Legacy `/api/workspaces/:workspaceId/tasks` list/create contract; the workspace page's stream paths are Conversation message/resume/reconnect paths.
- Legacy Task SSE and Conversation Stream exist and remain separate contracts. No v2 SSE was added, aliased, or implied by this remediation.
- Runtime Specification Migration Step 3 defines future Durable Events and `GET /api/runs/:runId/events` plus `GET /api/runs/:runId/stream`. Implementing that target would expand the Task-domain data model, Event Store/Repository, cursor/retention behavior, API contract, Web consumer, and migration scope.
- Future v2 Run Events, SSE, cursor, retention, Event Store, Web consumer, and required migration are deferred to an independently planned M3 Cutover work item. OD-36 does not authorize Migration 012 or any M3 implementation.
