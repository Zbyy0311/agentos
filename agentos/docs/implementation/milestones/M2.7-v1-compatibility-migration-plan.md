## 2. Objective

Define an explicit, lossless, operator-invoked v1 compatibility migration boundary that can preserve Legacy TaskItem data without silently mapping it into canonical Task/Run history. Freeze Migration 011 as the SQLite foundation for a transactional data-migration Registry and lossless Legacy Task compatibility storage. Preserve all M2.6 aggregate boundaries and defer final JSON/API/Web retirement to M2.8.

## 3. Non-goals

- No canonical Task bulk mapping from Legacy TaskItem.

- No historical Run synthesis.

## 4. Architecture Invariants

1. Workspace/Agent/Provider, Legacy TaskItem Runtime, Legacy Task compatibility copy, Task-domain Task/Run, and Conversation AgentRun/Execution retain distinct aggregate ownership.
2. Workspace/Agent/Provider and Task-domain Task/Run remain SQLite-canonical.
3. Legacy TaskItem Runtime remains JSON-canonical through M2.7.
4. Legacy compatibility rows are a lossless migration target and never become the Runtime source in M2.7.
5. `agent_runs`/`executions` remain separate from Task-domain `runs`.
6. Existing boot adoption remains unchanged; new M2.7 migration writes require explicit operator invocation.
7. Tombstones win over JSON. Existing SQLite aggregates are never silently overwritten by JSON.
8. Malformed migration input fails closed or is quarantined; it never becomes an empty successful import.
9. Raw Secret, Prompt, Message, output, full source path, stack, SQL, and user payload are excluded from logs and reports.
10. M2.8 owns final JSON read/write retirement, API/Web cutover, Bridge retirement, and readiness claims.
11. Historical Task-domain Run synthesis is prohibited in M2.7.
12. Workspace JSON read retirement only in M2.8.
13. Legacy Task JSON read retirement only in M2.8.

## 8. Migration 011 Required — Exact Planning Contract

It introduces exactly two data tables, their indexes, and their database-enforced immutability triggers. It is not implemented by this commit.

### 8.1 Registry DDL contract

```sql
CREATE TABLE legacy_data_migrations (
  id TEXT PRIMARY KEY,
  migration_kind TEXT NOT NULL
    CHECK (migration_kind IN ('workspace_adoption', 'legacy_task_item_import')),
  source_key TEXT NOT NULL
    CHECK (source_key IN ('workspaces.json', 'tasks.json')),
  scope_kind TEXT NOT NULL
    CHECK (scope_kind IN ('global', 'workspace')),
  scope_key TEXT NOT NULL CHECK (scope_key <> ''),
  canonical_workspace_id TEXT REFERENCES workspaces(id) ON DELETE SET NULL,
  source_hash TEXT NOT NULL
    CHECK (length(source_hash) = 64 AND source_hash = lower(source_hash)
           AND source_hash NOT GLOB '*[^0-9a-f]*'),
  payload_hash TEXT
    CHECK (payload_hash IS NULL OR (length(payload_hash) = 64 AND payload_hash = lower(payload_hash)
           AND payload_hash NOT GLOB '*[^0-9a-f]*')),
  hash_algorithm TEXT NOT NULL DEFAULT 'sha256'
    CHECK (hash_algorithm = 'sha256'),
  source_schema_version INTEGER CHECK (source_schema_version IS NULL OR source_schema_version >= 1),
  compatibility_schema_version INTEGER NOT NULL
    CHECK (compatibility_schema_version = 1),
  status TEXT NOT NULL
    CHECK (status IN ('running', 'completed', 'failed', 'quarantined')),
  attempt INTEGER NOT NULL CHECK (attempt >= 1),
  revision INTEGER CHECK (revision IS NULL OR revision >= 1),
  entity_count INTEGER NOT NULL DEFAULT 0 CHECK (entity_count >= 0),
  error_code TEXT,
  created_at TEXT NOT NULL,
  started_at TEXT NOT NULL,
  finished_at TEXT,
  updated_at TEXT NOT NULL,
  CHECK (
    (migration_kind = 'workspace_adoption' AND source_key = 'workspaces.json')
    OR (migration_kind = 'legacy_task_item_import' AND source_key = 'tasks.json')
  ),
  CHECK (
    (migration_kind = 'legacy_task_item_import' AND scope_kind = 'workspace')
    OR (migration_kind = 'workspace_adoption' AND scope_kind IN ('global', 'workspace'))
  ),
  CHECK (
    (status = 'running' AND payload_hash IS NULL AND source_schema_version IS NULL
      AND revision IS NULL AND finished_at IS NULL AND error_code IS NULL)
    OR (status = 'completed' AND payload_hash IS NOT NULL AND source_schema_version IS NOT NULL
      AND revision IS NOT NULL AND revision >= 1 AND finished_at IS NOT NULL AND error_code IS NULL)
    OR (status IN ('failed', 'quarantined') AND revision IS NULL
      AND finished_at IS NOT NULL AND error_code IS NOT NULL)
  ),
  CHECK (
    (scope_kind = 'global' AND scope_key = 'global' AND canonical_workspace_id IS NULL)
    OR (scope_kind = 'workspace' AND scope_key <> '')
  ),
  UNIQUE (migration_kind, source_key, scope_kind, scope_key, attempt)
);

CREATE UNIQUE INDEX legacy_data_migrations_completed_scope_source_hash
  ON legacy_data_migrations (
    migration_kind, source_key, scope_kind, scope_key, source_hash
  ) WHERE status = 'completed';

CREATE UNIQUE INDEX legacy_data_migrations_one_running_per_scope
  ON legacy_data_migrations (migration_kind, source_key, scope_kind, scope_key)
  WHERE status = 'running';

CREATE TABLE legacy_task_items (
  workspace_scope_id TEXT NOT NULL,
  canonical_workspace_id TEXT REFERENCES workspaces(id) ON DELETE SET NULL,
  legacy_task_id TEXT NOT NULL,
  revision INTEGER NOT NULL CHECK (revision >= 1),
  migration_id TEXT NOT NULL REFERENCES legacy_data_migrations(id) ON DELETE NO ACTION,
  source_hash TEXT NOT NULL
    CHECK (length(source_hash) = 64 AND source_hash = lower(source_hash)
           AND source_hash NOT GLOB '*[^0-9a-f]*'),
  payload_hash TEXT NOT NULL
    CHECK (length(payload_hash) = 64 AND payload_hash = lower(payload_hash)
           AND payload_hash NOT GLOB '*[^0-9a-f]*'),
  source_schema_version INTEGER NOT NULL CHECK (source_schema_version >= 1),
  compatibility_schema_version INTEGER NOT NULL
    CHECK (compatibility_schema_version = 1),
  payload_json TEXT NOT NULL CHECK (json_valid(payload_json) = 1),
  created_at TEXT NOT NULL,
  PRIMARY KEY (workspace_scope_id, legacy_task_id, revision),
  UNIQUE (migration_id, workspace_scope_id, legacy_task_id)
);

CREATE INDEX legacy_task_items_current_lookup
  ON legacy_task_items (workspace_scope_id, legacy_task_id, revision DESC);

CREATE TRIGGER legacy_task_items_reject_update
BEFORE UPDATE ON legacy_task_items
WHEN NOT (
  OLD.canonical_workspace_id IS NOT NULL
  AND NEW.canonical_workspace_id IS NULL
  AND NEW.workspace_scope_id IS OLD.workspace_scope_id
  AND NEW.legacy_task_id IS OLD.legacy_task_id
  AND NEW.revision IS OLD.revision
  AND NEW.migration_id IS OLD.migration_id
  AND NEW.source_hash IS OLD.source_hash
  AND NEW.payload_hash IS OLD.payload_hash
  AND NEW.source_schema_version IS OLD.source_schema_version
  AND NEW.compatibility_schema_version IS OLD.compatibility_schema_version
  AND NEW.payload_json IS OLD.payload_json
  AND NEW.created_at IS OLD.created_at

BEGIN
  SELECT RAISE(ABORT, 'LEGACY_TASK_ITEM_IMMUTABLE');
END;

CREATE TRIGGER legacy_task_items_reject_delete

BEGIN
```

### 8.2 DDL semantics

- `legacy_data_migrations` uses explicit `scope_kind`/`scope_key`: `global/global` represents a global source such as malformed `workspaces.json`; `workspace/<Legacy-or-Canonical-ID>` represents a Workspace candidate or migration unit. `canonical_workspace_id` is nullable and uses `ON DELETE SET NULL`.
- `legacy_task_items` uses `workspace_scope_id + legacy_task_id + revision` as its append-only identity. Its nullable `canonical_workspace_id` uses `ON DELETE SET NULL`; Workspace deletion never fails because of compatibility evidence.
- `source_key` is a logical source name only. Full source file paths are not stored.
- `source_hash` is lowercase hexadecimal SHA-256 of the exact UTF-8 source file bytes. `payload_hash` is lowercase hexadecimal SHA-256 of canonical UTF-8 JSON.
- Canonical JSON sorts object keys recursively, preserves array order, emits no insignificant whitespace, uses UTF-8, and applies one stable number representation. The aggregate Registry payload hash is computed from the ordered Workspace or TaskItem payload set; each Legacy Task row also stores its item payload hash.
- `source_schema_version` identifies the parsed v1 source shape. `compatibility_schema_version = 1` identifies this table contract.
- Allowed `migration_kind` values are exactly `workspace_adoption` and `legacy_task_item_import`; allowed `source_key` values are exactly `workspaces.json` and `tasks.json`.
- Allowed statuses are exactly `running`, `completed`, `failed`, and `quarantined`. `running` requires `payload_hash IS NULL`, `source_schema_version IS NULL`, `revision IS NULL`, `finished_at IS NULL`, and `error_code IS NULL`. `completed` requires all three parsed fields non-NULL, `revision >= 1`, `finished_at IS NOT NULL`, and no `error_code`. `failed` and `quarantined` require `revision IS NULL`, `finished_at IS NOT NULL`, and `error_code IS NOT NULL`; their parsed fields may be NULL or already known.
- The only Registry state transition is `running -> completed`, `running -> failed`, or `running -> quarantined`; terminal states cannot transition again and cannot be deleted. The only UPDATE exception after or during any state is non-null `canonical_workspace_id -> NULL` with every other column unchanged, caused by Workspace deletion.
- All timestamps are UTC RFC3339 strings with millisecond precision and `Z` suffix. `created_at` and `started_at` are immutable; `finished_at` is written exactly once during terminal transition; `updated_at` records the permitted transition. The database enforces state combinations and the Service validates timestamp format.
- Evidence payload, hashes, scope, Attempt, Revision, and status history are immutable. The sole Evidence UPDATE exception is non-null `canonical_workspace_id -> NULL` caused by Workspace deletion; it never permits `NULL -> non-null`, `non-null -> different non-null`, or any simultaneous column change. DELETE remains forbidden for both tables.
- `attempt` increments only after both Ownership layers, read-only source preflight, and write-intent Backup verification pass and an Attempt Reservation write transaction starts. CLI arguments, absolute paths, source existence/readability, source bytes, and source hash are read-only preflight; any failure creates no Backup or Attempt. A parser failure after Reservation creates a `quarantined` Attempt. Running, failed, quarantined, and interrupted Attempts consume their unique Attempt number.
- Attempt allocation uses one SQLite write transaction (`BEGIN IMMEDIATE`, two-layer-owner stale-Running reconciliation, deterministic next-number allocation, Registry INSERT, COMMIT); it never uses a non-transactional `MAX + 1`. The `legacy_data_migrations_one_running_per_scope` partial unique index is database defense in depth and does not replace database-wide Migration Ownership or Project Runtime Quiescence Ownership.
- `revision` represents the accepted canonical Payload Revision. After both Ownership layers and read-only source preflight, a completed exact-source match on `migration_kind`, `source_key`, `scope_kind`, `scope_key`, `source_hash`, `compatibility_schema_version`, and `hash_algorithm` is checked before Backup and Attempt Reservation and is a no-op. The old row supplies `payload_hash`, `source_schema_version`, `revision`, and `entity_count` evidence; Parser and Backup Provider are not called. A source-byte-only hash change with identical Payload Hash creates a new completed Attempt, reuses the latest accepted Revision, and writes no new `legacy_task_items`. An accepted Payload Hash change creates `latest_revision + 1` and a complete TaskItem snapshot. Workspace payload compatible with existing SQLite creates one new Revision; Workspace payload conflict creates a quarantined Attempt with `revision=NULL` without overwriting SQLite.
- Deterministic hash branches are fixed: Exact Source Hash is no-op; Source-only hash change with the same Payload Hash creates a completed Attempt reusing the Revision; Payload Hash change creates one new Revision and full compatibility snapshot; Workspace-compatible Payload change creates one new Revision; Workspace conflict creates a quarantined Attempt without overwriting SQLite.
- `legacy_task_items` is append-only and versioned by `(workspace_scope_id, legacy_task_id, revision)`. Existing rows are never updated or deleted by M2.7 except the FK-driven non-null canonical Workspace link nulling; only a new accepted Payload Hash can INSERT a new Revision.
- `payload_json` is the semantic-lossless parsed TaskItem JSON for the accepted Legacy JSON domain, including accepted Unknown Fields and outputs. The table is storage only; it cannot automatically create canonical Task, Run, Snapshot, Stage, or Artifact records.
- Failed or quarantined units commit no compatibility rows and no completed Registry marker. Completed Registry and compatibility rows commit in the same SQLite transaction.
- Database triggers permit only the exact FK-driven link nulling UPDATE and reject every other `legacy_task_items` UPDATE, every Registry DELETE, every terminal Registry UPDATE except link nulling, and every identity-field mutation with stable errors `LEGACY_TASK_ITEM_IMMUTABLE`, `LEGACY_DATA_MIGRATION_IMMUTABLE`, and `LEGACY_DATA_MIGRATION_DELETE_FORBIDDEN`. Migration checksum coverage includes Tables, Indexes, and Triggers.
- Migration Registry order is exactly existing `001` through `010`, followed by `011-legacy-data-migration-foundation`. `_schema_migrations` remains the schema Registry and is not reused as the data Registry.
- A Sidecar Manifest is not the authoritative marker and is not used as a completion source.

### 8.3 Semantic-lossless JSON contract

The contract is **semantic-lossless compatibility payload for the accepted Legacy JSON domain**. It is not a claim that arbitrary JSON bytes can be reproduced byte-for-byte.

- The strict parser runs after Attempt Reservation; duplicate Object Keys and other parser rejection inputs create a `quarantined` Attempt with no compatibility rows.
- Accepted Unknown Fields are preserved in `payload_json`; Array Order is preserved; Object Keys are recursively sorted only for canonical hashing.
- Canonical JSON uses UTF-8, JSON-standard string escaping, no insignificant whitespace, and one stable representation for accepted numbers.
- Numeric Tokens that cannot be represented without semantic loss are rejected. Integers outside the safe integer range are rejected. Numbers that cannot be stably re-serialized are rejected. `NaN`, `Infinity`, and other non-JSON numeric values are rejected.
- Rejected input fails closed and never creates Empty Success. Source bytes remain evidenced by `source_hash`; accepted semantic JSON is retained by `payload_json` and evidenced by `payload_hash`.
- `source_hash` is SHA-256 of exact source bytes. `payload_hash` is SHA-256 of canonical semantic JSON. Both are lowercase hexadecimal 64-character values.

### 8.4 Attempt Transaction Lifecycle

1. **Basic validation:** validate argument presence, `--kind`, `--mode`, confirmation format, absolute-path syntax, and the basic `projectRoot`/`databasePath` relationship. Failure acquires no Ownership, creates no Backup, creates no Attempt, and writes no Registry state.
2. **Project Runtime Quiescence Ownership:** canonicalize `projectRoot` from absolute `--source-root` and call existing `acquireServerOwnership(projectRoot)`. A live Server Owner or unknown Ownership state returns `LEGACY_DATA_MIGRATION_RUNTIME_ACTIVE` with Exit Code 5; it creates no Attempt, Registry write, Backup, Running-row mutation, or JSON write.
3. **Database-wide Migration Ownership:** after Project Ownership succeeds, acquire the M2.7 database-wide lock. Its identity is the protocol constant `agentos:m2.7:legacy-data-migration-lock:v1` plus canonical absolute `databasePath`, never migration Scope. Failure returns `LEGACY_DATA_MIGRATION_ACTIVE` with Exit Code 5 and releases Project Ownership; it creates no Attempt or migration write.
4. **Read-only source preflight:** while both Ownership layers are held, validate source existence/readability, read exact source bytes, and compute lowercase SHA-256 `source_hash`. Do not run Parser, create Backup, call Backup Provider, create Attempt, or write Registry/JSON.
5. **Exact Source Hash Fast No-op:** while both Ownership layers are held and before any Backup, query the completed exact-source key. If found, return old-row evidence (`payload_hash`, `source_schema_version`, `revision`, `entity_count`) without running Parser, calling Backup Provider, creating Backup/Attempt, or writing Registry/compatibility/JSON state; then release Database Ownership followed by Project Ownership.
6. **Write-intent Backup preflight:** only after the exact-source lookup misses, create and verify a complete SQLite database Backup and the current Scope's JSON Backup. Verify Backup existence, Backup Hash, SQLite `integrity_check`, SQLite `foreign_key_check`, and JSON exact-byte hash. Failure creates no Attempt or Registry/source write and returns a stable Backup error.
7. **Stale reconciliation and Attempt Reservation:** while both Ownership layers remain held, use one `BEGIN IMMEDIATE` transaction to inspect only the target Scope's Running Attempt, update stale Running to `failed` with `LEGACY_DATA_MIGRATION_INTERRUPTED`, `revision=NULL`, and current `finished_at`/`updated_at`, allocate the next Attempt, INSERT the new Running row, and COMMIT. No reconciliation or Attempt creation is allowed without both Ownership layers.
8. **Parser and terminal processing:** while both Ownership layers remain held, run strict Parser after Reservation; Parser rejection becomes Quarantined, canonical conflict becomes Quarantined, operational failure becomes Failed, and accepted success becomes Completed. Compatibility rows and Completed transition remain atomic; no canonical Task/Run synthesis, JSON deletion, or automatic fallback.
9. **Release Ownership:** after terminal, no-op, or failure result, release Database-wide Migration Ownership first and Project Runtime Quiescence Ownership second. Any intermediate exception performs best-effort release of all acquired Ownership. Process exit must release both OS-owned mechanisms.

Exact Source Hash no-op is evaluated after both Ownership layers and read-only source preflight, but before Backup. Source-only hash change creates a new Completed Attempt reusing the latest accepted Revision. Accepted Payload Hash change creates a new Completed Attempt and `latest_revision + 1`. Workspace conflict creates a Quarantined Attempt with `revision=NULL`.

### 8.5 Migration Execution Lock contract

Migration Execution Lock is the second Ownership layer for one canonical SQLite database. It is not a Sidecar completion manifest, Migration Registry, success evidence, or recovery source; SQLite Registry state remains authoritative.

- **Database-wide lock identity:** derive a complete SHA-256 lock token only from protocol constant `agentos:m2.7:legacy-data-migration-lock:v1` and canonical absolute `databasePath`. Do not include `migration_kind`, `source_key`, `scope_kind`, `scope_key`, Workspace ID, or any other Scope value. The full path and token are never printed.
- **Serialization:** all M2.7 Apply Scopes on one database compete for the same lock and cannot run in parallel. Different databases may independently acquire their own lock. Scope remains Registry, Attempt, Revision, and Quarantine identity only.
- **Ownership mechanism:** Windows uses Named Pipe or a strict OS-owned equivalent; non-Windows uses collision-aware loopback ownership. The handshake validates the complete SHA-256 token. Unknown owner, malformed handshake, timeout, connection reset, or candidate collision fails closed. No ordinary filesystem lockfile and no probe-then-unlink.
- **Runtime coordination:** this lock is acquired only after existing Project Runtime Quiescence Ownership succeeds. It must never be acquired in the reverse order. If Database-wide Ownership fails, release Project Ownership before returning.
- **Failure:** return `LEGACY_DATA_MIGRATION_ACTIVE` with Exit Code 5; create no Attempt, Backup, Registry write, Running-row mutation, or JSON write. A contender never performs stale reconciliation.
- **Release:** terminal/no-op/failure release order is Database-wide Migration Ownership, then Project Runtime Quiescence Ownership. OS process termination must automatically release both Ownership layers.

### 8.6 Project Runtime Quiescence Ownership contract

- P1 reuses read-only `apps/server/src/serverOwnership.ts` via `acquireServerOwnership(projectRoot)`; it does not modify or duplicate that implementation. The existing source uses OS-owned Windows Named Pipe and collision-aware non-Windows loopback mechanisms (`serverOwnership.ts:270-298`).
- `projectRoot` is the canonical absolute `--source-root`; `apps/server/src/projectRoot.ts` remains read-only (`resolveProjectRoot` is existing path logic).
- Successful Project Ownership proves no AgentOS Server currently owns that Project Root and prevents a new Server from acquiring the same ownership during migration. Existing `ServerAlreadyRunningError`, `ServerOwnershipUnavailableError`, or unknown state maps to `LEGACY_DATA_MIGRATION_RUNTIME_ACTIVE`.
- Logs never print Project Root, server Named Pipe, port candidate set, or complete Ownership token. The migration adapter exposes one lease/handle and releases it on every terminal/no-op/failure path.

### 8.7 Backup and Restore Boundary

1. Backup is a complete SQLite database Backup, not a Scope-local Backup. The corresponding JSON Backup covers the current explicit Scope.
2. Because restore is whole-database, all M2.7 Apply Scopes on one database path are serialized by the database-wide lock.
3. Backup creation and verification occur while AgentOS Server Runtime is quiescent under Project Runtime Quiescence Ownership.
4. P1 implements only Backup creation and verification primitives; P2/P3 do not implement automatic Production Restore.
5. P5 may rehearse restore only against a database copy and synthetic JSON; it must not write real user sources.
6. Any real committed-unit restore requires independent Owner authorization, stopped AgentOS Server, both Ownership layers, and explicit acceptance that whole-database restore revokes every database write after Backup creation.
7. Without independent restore authorization, a migration failure never overwrites the current database from a Backup.
8. Processing Transaction failure first relies on SQLite rollback; it does not automatically restore the whole database.
9. `No automatic fallback after migration failure` remains unchanged.
