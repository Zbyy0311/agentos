## Migration 003 — Tables Created

### workspaces (full data model: 17 columns)
```
id | name | description | root_path | canonical_root_path UNIQUE |
repository_type | default_branch | default_agent_id | default_provider_config_id |
default_workflow_definition_id | default_policy_profile_id | status | settings_version |
git_enabled | memory_enabled | last_opened_at | created_at | updated_at | archived_at |
deleted_at | version
```

### provider_configurations (workspace FK + unique name constraint)
```
id | workspace_id FK→workspaces(id) | name | provider_type | adapter_id |
runtime_mode | executable | args_template_json | model |
environment_profile_id | secret_profile_id | working_directory_mode |
custom_working_directory | capabilities_json | timeout_policy_json |
approval_mode | output_mode | enabled | version | created_at | updated_at | archived_at
UNIQUE(workspace_id, name)
INDEX idx_provider_config_workspace_enabled(workspace_id, enabled)
```

### agent_profiles
```
+ provider_config_id TEXT REFERENCES provider_configurations(id)
+ INDEX idx_agent_profiles_provider_config(provider_config_id)
```

## Remediation Summary

| Issue | Fix |
|---|---|
| Migration 003 schema not matching data model | Added `description`, repository_type, status, settings_version, archived_at, deleted_at, default-* columns + FK on provider_configurations(workspace_id→workspaces) + UNIQUE(workspace_id, name) + FK on agent_profiles(provider_config_id→provider_configurations) + 3 INDEX statements |
| 4 legacy migration test regressions | Applied baseline schemas in tests, re-activated `migrateAgentEventSequences` + `migrateLegacyExecutionRuns` in constructor |
| JSON writes not stopped | Removed `legacy.saveWorkspaces()` from `saveWorkspaces()` and `updateAgentProfile()`; removed `legacy.saveWorkspaces()` from `migrateLegacyKimiWorkspaceConfigs()` (was writing back to JSON at every startup) |
| WorkspaceManager still uses full-list operations | Rewired to `workspaceRepo.insert/findById/update/deleteById` + `findByCanonicalPath` for dedup |
| New workspaces lack default agents + provider configs | `WorkspaceManager.create()` now atomically creates `workspaces` row + `agent_profiles` + `provider_configurations` entries for all DEFAULT_WORKSPACE_AGENTS, linked via `provider_config_id` |
| Provider API workspace isolation bypass | Added workspace membership checks on GET/PUT/DELETE by-id endpoints; stable error codes (`PROVIDER_CONFIG_NOT_FOUND`, `VERSION_CONFLICT`, `PROVIDER_CONFIG_IN_USE`); removed `(store as any).database` via `getDatabase()` |
| Provider API lacks real OCC | `expectedVersion` is now **required** in PUT requests (400 if omitted); repository uses caller-provided version in WHERE clause instead of re-reading it |
| Agent ↔ Provider binding missing | Added `providerConfigId` to `WorkspaceAgent`/`AgentProfile` types; selects `provider_config_id` in `listAgentProfiles()`; maps in `toAgentProfile()` |
| Legacy migration fragile | Per-workspace idempotency (uses `exists(ws.id)`) instead of `count() > 0` guard; catches only known constraint violations |
| Deleted workspace resurrects on restart | Persistent `_workspace_tombstones` SQLite table tracks deleted workspace IDs; JSON fallback excludes tombstoned IDs |
| Agent profile provider_config_id FK in DELETE in-use check | Changed from referencing non-existent `run_stages` table to checking `agent_profiles WHERE provider_config_id = ? AND enabled = 1` |
| `deleteWorkspace` FK failure | Added `DELETE FROM provider_configurations WHERE workspace_id = ?` before deleting workspace row |
