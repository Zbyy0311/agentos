## 本轮已落实的修复

1. Kimi legacy migration 只对内存中的深拷贝做归一化，不再调用 `legacy.saveWorkspaces()`，JSON Hash 回归测试通过。
2. `WorkspaceManager.create()` 使用一个外层 `inTransaction()`，通过 `insertWithinTransaction()` 写入 Workspace、Provider Configuration 和 Agent Profile；任一写入失败都会整体回滚。
3. Workspace 存在性判断以 SQLite `workspaceRepo.exists()` 为主，保留 legacy JSON fallback；SQLite-only Workspace 可以立即创建 Conversation，重启后仍能加载默认 Agent。
4. `listAgentProfiles()` JOIN `provider_configurations`，兼容字段由 Provider Configuration 投影；Provider 更新后 Agent 的 provider、CLI 命令、参数和 model 会随之变化。
5. Legacy Workspace/Agent migration 按 Workspace 处理，创建历史 Provider Configuration 并建立绑定；只忽略已识别的 canonical path 冲突，其余数据库/Schema/FK/未知错误会显式失败并保留 cause。
6. `_workspace_tombstones` 移入版本化 Migration 004，构造函数不再临时创建永久表；删除标记重启后仍过滤 JSON fallback。
7. Provider Repository 的 `update()`、`archive()` 强制要求 `expectedVersion`；Provider PUT/DELETE 路由均使用客户端版本，过期版本返回 409，启用 Agent 引用的 Provider archive 返回 409。
8. `saveWorkspaces()` 改为不写 JSON，并在一个 SQLite 事务内保存传入的 Workspace/Provider/Agent 聚合，避免关闭 JSON 回写后丢失旧 Store 接口的 Agent。
9. `Workspace.agents` 返回 `providerConfigId`，Provider `model = NULL` 时不回退旧 Agent model；`5ba72b1a` 中的 agent-core/Runtime Mock 注入已由 `236fcc79` 撤回，最终净差异不修改 `packages/agent-core/**`。
