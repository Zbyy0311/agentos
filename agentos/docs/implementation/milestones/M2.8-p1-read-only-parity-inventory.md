Field equality is required in addition to row counts. Every domain requires its mapped aggregate, every compared record must contain every required field, and `requiresBehaviorParity=true` requires a present, non-empty, 64-hex behavior digest on both sides. Missing or invalid required fields/behavior are `malformed`; they are never silently treated as equal. A behavior mismatch is non-equal even if fields match.

## 6. Read-only comparator design

`M2ReadOnlyParityService.compare()` is a pure deterministic operation over immutable input snapshots, exact source bytes, the read-only Inventory type, and `node:crypto`.

- Source identity reports source kind, redacted source key/scope, exact-byte SHA-256, optional previous source hash, and an opaque database identity.
- Object keys, field names used for comparison, records, and evidence are stably ordered; equal logical input produces the same result and comparison hash.
- Input records, arrays, field maps, and source bytes are never mutated.
- The public class exposes only `compare`; there is no write/save/update/delete/apply interface.
- The service has no Store/Repository dependency, file or SQLite access, subprocess, route, flag, migration, dual-read, or quarantine-record side effect.
- A mismatch emits only domain ID, opaque record-key digest, field name, classification, expected/actual value digests, redacted reason, and safe count.

### Normalized parity value contract

Allowed field values are `null`, strings, booleans, finite numbers, `Uint8Array` represented only by SHA-256, and readonly arrays/plain objects recursively composed of those values. `undefined`, functions, symbols, BigInt, `NaN`, infinities, `Date`, `Map`, `Set`, `RegExp`, `Error`, class instances, cycles, symbol-keyed properties, accessors, and other non-data properties are `malformed` and never throw out of `compare()`.

Only `requiredLogicalFields` and `allowedOptionalFields` may appear in a record. Unknown field names are classified as `malformed`; evidence uses the fixed safe field name `unknown_field` and hashes the unknown name without emitting it. Paths, credentials, and user content therefore cannot enter `evidence.fieldName` or raw evidence.

### Cross-environment ordering

All record, field, Set-derived, and evidence ordering uses an explicit UTF-16 code-unit comparator. No `localeCompare` dependency remains. The same logical Unicode-key input therefore produces the same evidence order and comparison hash across Windows/Linux and locale settings.

### Classification taxonomy

The only classifications are `equal`, `missing_legacy`, `missing_canonical`, `mismatch`, `malformed`, `duplicate`, `tombstone`, `conflict`, and `changed_source`. The implementation does not emit `silently_applied`, `best_effort_success`, `repaired`, or `overwritten`.

### Recommended quarantine disposition

`malformed`, `duplicate`, `tombstone`, `conflict`, `changed_source`, `mismatch`, and either missing-record classification are non-success evidence and must not be auto-applied or converted into a quarantine record by P1. They require the owning P2/P3 decision. Only field parity plus behavior parity plus unchanged source identity can classify a record as `equal`. A tombstone is never treated as an ordinary missing record.

## 7. Redaction and no-leak rules

Evidence does not include raw JSON bytes, complete records, provider credentials, command arguments, task bodies, conversation messages, or full local/database paths. Source keys, scopes, database identities, and record keys become SHA-256 digests when path-like or otherwise opaque. Value evidence is digest-only. No production fixture is represented as a reader or writer.
