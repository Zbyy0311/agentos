## 39. Project-Root Ownership Remediation (PR #3 MEDIUM + LOW)

### 39.1 Findings and owner decision

- MEDIUM: startup queued recovery had no enforced single-server ownership and could fail a live queued Run from another process.
- LOW: startup recovery failure leaked raw backend error, stack, and local source paths.
- Owner Decision: **Project-Root IPC Ownership Lock**, independent of HTTP PORT.
- Previous Head: `4195403b`; Ownership Remediation Code Commit: `c2828aac`.

### 39.2 Mechanism

- Ownership key: SHA-256 (32 hex chars) over the canonicalized Project Root (`resolve` + `realpathSync.native` when the path exists, lowercased on Windows). The full Project Root never appears in the endpoint name.
- Windows: exclusive Named Pipe `\\.\pipe\agentos-server-<hash>` via `node:net`; the first-instance bind is OS-enforced, a conflict maps to `SERVER_ALREADY_RUNNING`, and process death releases the pipe automatically.
- Linux/macOS: Unix Domain Socket `<tmpdir>/agentos-server-<hash>.sock`; on bind conflict the endpoint is probed for a live owner first, and only a confirmed-stale socket-type file is removed before a bounded rebind. Regular files, directories, and symlinks fail closed with `SERVER_OWNERSHIP_UNAVAILABLE`; nothing is deleted based on file age.
- Ownership is acquired before `new SqliteStore`, Task Runtime recovery, Conversation recovery, Worktree reconcile, Retention, route mounting, and HTTP listen; a second instance exits before any Task/Run/JSON mutation.
- `void worktreeManager.reconcile()` now runs only after ownership + recovery + successful HTTP listen; the Retention one-shot run and timer also start only after listen.
- HTTP listen is Promise-wrapped (`listening`/`error`); bind failure closes the store, releases ownership, exits non-zero with stable `SERVER_LISTEN_FAILED`, and never prints raw `EADDRINUSE`.
- Single sanitized startup boundary: `SERVER_ALREADY_RUNNING` reports `startup blocked`; `STARTUP_RECOVERY_FAILED`, `SERVER_LISTEN_FAILED`, and unknown errors (`SERVER_STARTUP_FAILED`) report `startup failed`. No raw message, stack, SQLite/SQL text, trigger name, local path, legacy error, or cause escapes to console or diagnostics; diagnostics record only stable code, pid, instanceId, and phase.
- Recovery errors are wrapped as internal `STARTUP_RECOVERY_FAILED` without breaking the original transaction rollback; unified shutdown (SIGINT/SIGTERM/SIGHUP with existing exit codes) stops HTTP, stops the Retention timer, closes the store, and releases ownership without rewriting Task/Run state.
- Not adopted: PID file, plain JSON lock file, createdAt timeout, Migration 007 or any SQLite migration, HTTP PORT or `start-dev.ps1` as ownership, new npm dependency, DB lease, Run owner token, or queued Run schema change.

## 41. Candidate-Set Ownership Remediation (HIGH)

### 41.1 Finding

- HIGH: collision-aware loopback ownership could assign two candidate ports to the same Project Root after another Root released an earlier candidate. Sequence: Root A takes P1; Root B reads A's valid different hash on P1 and falls back to P2; A releases P1; a second B process binds the freed P1 while the original B still holds P2 — two ownership endpoints for one Project Root.
- Root cause: only the port being bound was checked; the candidate set was not treated as one ownership namespace.

### 41.2 Resolution

- **Full pre-bind sweep**: before any bind, the entire candidate set is probed in stable order. Any `same-owner` anywhere → `SERVER_ALREADY_RUNNING`; any `unknown` anywhere → `SERVER_OWNERSHIP_UNAVAILABLE`; `other-owner` is recorded as legitimately occupied; acquisition proceeds only with no same-owner, no unknown, and at least one free candidate.
- Probe outcomes are now four-valued: `free` (ECONNREFUSED), `same-owner` (valid `AGENTOS_OWNER_V1` same hash), `other-owner` (valid different hash), `unknown` (timeout, reset, malformed, overlong, non-AgentOS, or indeterminate).
- **Bind step**: bind the first sweep-free candidate; on EADDRINUSE re-probe (same-owner → ALREADY_RUNNING; other-owner → next known-free candidate; unknown/free-race → UNAVAILABLE); any non-EADDRINUSE bind failure → `SERVER_OWNERSHIP_UNAVAILABLE` with no fall-through.
- **Full post-bind verification sweep**: after a successful bind, every other candidate is re-probed; a discovered same-owner or unknown releases the just-bound server and fails (`SERVER_ALREADY_RUNNING` / `SERVER_OWNERSHIP_UNAVAILABLE`). Two applicants may both safely fail; never both succeed.
- **Connection lifecycle**: ownership servers track accepted sockets, write the bounded handshake, destroy the socket after flush, enforce a short socket timeout, and `release()` destroys all accepted sockets before `server.close`, so a held client can never block release, shutdown, cleanup, or re-acquire. Applies to both loopback and Windows Named Pipe ownership.
- Windows Named Pipe mechanism unchanged; `index.ts` unchanged (stable classification already covered both codes); `serverStartup.test.ts` frozen with zero diff.
