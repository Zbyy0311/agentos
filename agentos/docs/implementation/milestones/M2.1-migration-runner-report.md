## 4. `_schema_migrations` DDL

```sql
CREATE TABLE _schema_migrations (
  migration_id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  checksum TEXT NOT NULL,
  applied_at TEXT NOT NULL,
  execution_ms INTEGER NOT NULL,
  app_version TEXT
);
```

## 5. Migration Interface

```typescript
interface Migration {
  id: string;         // numeric string, e.g. "001"
  name: string;       // human-readable
  checksum: string;   // frozen sha256 hex (first 16 chars)
  destructive?: true; // requires pre-backup
  apply(context: MigrationContext): void;
}

interface MigrationContext {
  db: MinimalDatabaseSync;  // { exec, prepare }
}

interface MigrationRecord {
  migrationId: string;
  name: string;
  checksum: string;
  appliedAt: string;
  executionMs: number;
  appVersion?: string;
}
```

## 6. Error Codes

| Code | Meaning |
|---|---|
| `MIGRATION_DUPLICATE_ID` | Registry has duplicate or invalid ID |
| `MIGRATION_CHECKSUM_MISMATCH` | Applied migration has different checksum than code |
| `MIGRATION_FAILED` | Migration apply() threw |
| `MIGRATION_SCHEMA_INCOMPATIBLE` | Legacy DB schema doesn't match baseline |
| `MIGRATION_LOCK_FAILED` | Reserved for concurrent access |
| `MIGRATION_INTEGRITY_FAILED` | integrity_check or foreign_key_check failed |

## 7. Checksum Strategy

- Sha256 over canonical DDL text (space-normalized)
- Computed deterministically via `crypto.createHash('sha256')`
- First 16 hex chars stored in `_schema_migrations.checksum`
- Checksum mismatch is a hard failure — DB is NOT modified

## 8. Transaction Strategy

```
BEGIN IMMEDIATE
  → migration.apply()
  → integrity_check + foreign_key_check
  → INSERT INTO _schema_migrations
COMMIT
```

On failure: ROLLBACK, no record written, migration can be retried.

## 9. Lock Strategy

`BEGIN IMMEDIATE` in SQLite guarantees no concurrent write transaction. Each migration runs in its own IMMEDIATE transaction. No explicit advisory lock is needed for single-process SqliteStore usage.

## 11. Legacy Adoption Strategy

```
Existing DB detected (has user tables, no _schema_migrations)
  → inspectSchema(): PRAGMA table_info, index_list, index_info on every table
  → buildExpectedBaseline(): apply DDL to in-memory temp DB, inspect same way
  → compareToBaseline(): structural diff (tables, columns, types, indexes, triggers)
  → isSchemaCompatible(): all checks must pass
  → compatible: record 001 as applied, original data preserved
  → incompatible: throw MIGRATION_SCHEMA_INCOMPATIBLE with full diagnostics
```

## 14. Backup Strategy

- `BackupProvider` interface: `{ backup(path: string): void }`
- `createFileBackupProvider(backupDir)` — copies file via `copyFileSync` before destructive migrations
- Backup failure prevents migration execution (MIGRATION_FAILED with cause)
- Non-destructive migrations skip backup
