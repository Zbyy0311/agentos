## Summary

Move workspaces from JSON-first to SQLite-first. Introduce `provider_configurations` as a
first-class entity separate from `agent_profiles`. Link agents to provider configs via
`provider_config_id` foreign key. Legacy JSON becomes read-only fallback, with a one-time
import at migration time.

## Architecture

```
Before M2.3:
  workspaces.json ──► JsonFileStore ──► SqliteStore.loadWorkspaces()
  agent_profiles table (SQLite)                saveWorkspaces() → JSON

After M2.3:
  workspaces table (SQLite) ◄── WorkspaceRepository (CRUD + version guard)
  provider_configurations table (SQLite) ◄── ProviderConfigurationRepository
  agent_profiles.provider_config_id FK → provider_configurations.id
  workspaces.json ──► read-only fallback for legacy entries
```

### Data Flow

1. **Read path:** SQLite workspaces table → compatibility projection with LEFT JOIN
   agent_profiles + provider_configurations → Workspace.agents[]
2. **Write path:** WorkspaceManager → WorkspaceRepository → SQLite (no JSON writes)
3. **Legacy import:** Migration 003 → one-time JSON→SQLite copy for all existing workspaces
4. **Fallback:** `loadWorkspaces()` reads SQLite first; for any workspace ID missing in
   SQLite but present in JSON, the JSON entry is imported on-the-fly (dual-read)

```sql
ALTER TABLE agent_profiles ADD COLUMN provider_config_id TEXT;
```

### Canonical Root Path
Normalized form = `path.resolve(rootPath)` on POSIX, `.toLowerCase()` on win32.
UNIQUE constraint on `canonical_root_path` prevents duplicate workspace registrations.

### ID Strategy
- New workspaces: `createEntityId('workspace')` → `ws_{26-char ULID}`
- Existing workspaces: preserve legacy 8-char IDs already in JSON
- Provider configs: `createEntityId('provider')` → `provider_{26-char ULID}`

## Backward Compatibility

### Workspace.agents Projection
`Workspace.agents` stays in the TypeScript type but becomes a compatibility projection:
```sql
SELECT w.*, ap.*, pc.*
FROM workspaces w
LEFT JOIN agent_profiles ap ON ap.workspace_id = w.id
LEFT JOIN provider_configurations pc ON pc.id = ap.provider_config_id
```
The result is assembled into `Workspace & { agents: WorkspaceAgent[] }`.

### API Stability
- GET/POST `/api/workspaces` — unchanged response shape
- GET `/api/agents/:workspaceId/status` — unchanged (reads `workspace.agents`)
- All existing routes continue to receive `Workspace` objects with `.agents` array
